## 页面操作

在「家庭成员」中，管理员可对其他成员选择「设为管理员」「取消管理员权限」「移出家庭」，每次都需确认。新管理员与现有管理员使用同一角色，拥有成长记录、成长测量、接种、孩子档案、成员和权限管理、回收站、空间设置、导出、日志、分享管理及家庭 AI 开关权限，也能继续授权其他成员。

所有管理员都不能移出家庭创建者或取消创建者权限，也不能移出自己或修改自己的角色。后端保留至少一位管理员，并在当前家庭范围内查找目标成员，不接受客户端传入家庭 ID。所有成员和角色变更记入操作日志；权限变更也通知目标成员。

取消管理员权限后，对方保留普通成员权限。角色从数据库逐次读取，下次请求即按最新权限判断，页面刷新后更新按钮。涉及管理员能力的写入在家庭行锁内再次核对身份，拒绝排队期间被移出或降权的旧请求；已经完成或已经返回给客户端的数据不能追回。

移出成员会删除家庭关系、取消该成员仍在生成的 AI 请求并撤销其创建的分享。其原有成长记录及账号保留，不连带删除其他人的资料。被移出的账号不能继续访问家庭，当前仍不支持同一账号重新加入家庭或切换家庭。

## 删除、恢复与彻底删除孩子档案

「家庭成员 → 孩子的小档案 → 删除档案」会将 `child.is_active` 改为 false。档案及关联资料从常规页面隐藏，只向本家庭管理员展示回收站档案列表。

- 成长记录保持各自原有的删除状态，照片视频、测量、接种、评论和标签均保留；不会进入对象删除队列。
- 隐藏期间不能新增该孩子的记录、测量、接种或 AI 请求，也不能通过旧编号修改、恢复、彻底删除记录、读取媒体或导出资料；应先恢复档案。
- 原有分享撤销，运行中的该孩子 AI 请求标记取消，并由已有周期检查终止后续生成。已开始返回的媒体或已发出的文本不能撤回。
- 「回收站 → 孩子档案回收站 → 恢复档案」将档案改回活动状态。之前正常的资料重新显示；之前已单独删除的记录仍留在记录回收站；旧分享不会重新启用。
- 档案回收站不释放存储配额，保留的媒体计入原有占用。
- 「回收站 → 孩子档案回收站 → 彻底删除」显示不可恢复的确认提示。确认后清理整份孩子档案，包括正常及已单独移入回收站的成长记录、照片视频、评论、标签关联、分享、关联通知、测量、接种和 AI 请求状态。家庭共享标签字典、其他孩子资料及家庭操作日志保留，并新增此次删除的审计记录。
- 删除关联数据与写入 `media_cleanup` 在同一事务中完成；任一步失败整体回滚。元数据删除后释放对应的业务配额，MinIO 文件由后台清理，失败保留任务重试。后端只接受本家庭非活动档案，先锁定家庭并重查管理员角色；若另一个管理员先恢复档案，旧页面上的彻底删除请求会被拒绝。

## 接口

路径前缀均为 `/api/growth`，需要登录，服务端校验管理员身份与家庭范围。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| DELETE | `/family/members/{id}` | 移出成员，id 为家庭成员关系 ID |
| PUT | `/family/members/{id}/role` | JSON `{"role":"admin"}` 授权，`{"role":"member"}` 撤销 |
| DELETE | `/children/{id}` | 将孩子档案及关联资料隐藏到档案回收站 |
| POST | `/children/{id}/restore` | 恢复孩子档案 |
| DELETE | `/children/{id}/purge` | 仅对档案回收站中的孩子，永久清理整份档案及关联资料 |

`GET /snapshot` 增加 `family.creatorId` 和 `archivedChildren`；后者仅管理员获得。正常记录、测量、接种、记录回收站和分享列表过滤已隐藏的档案。头像、普通登录和注册头像功能不变。
