# 拾光小助手 · 千问聊天与成长整理

本次为源码实现，未编译、未启动、未执行 SQL、未调用真实千问、未做接口或浏览器测试。以下描述实现路径，实际运行效果待手动验证。

## 启用

1. 在已经建好表的 `growth` 数据库中执行 `src/main/resources/growth/upgrade-ai-assistant.sql`。它新增 `ai_family_settings` 和 `ai_assistant_request`，不修改原有成长记录。新建数据库执行完整 `schema-mysql.sql` 已包含这两张表，无须再执行升级文件。
2. 沿用已有 `app.ai.providers.qwen` 的 enabled、base-url、api-key 和 model，前端不能覆盖模型、地址或密钥。模型客户端仍由现有 `AiProviderRegistry` 管理，不增加新的模型依赖，不改变原 AI 调试台。
3. 重新编译启动，刷新网站。家庭管理员打开「空间设置 → 拾光小助手 → 设置与使用」，阅读资料说明后开启。右下角助手面板中也提供同一开关；需要先有孩子档案。
4. 普通成员和管理员都可使用；仅管理员可开关。每次生成前需确认所选输入和资料会发送给千问。家庭开关初始为关闭；只是打开面板、查看测量或填写日记不会调用模型。

已经执行过助手升级 SQL 的项目，本次连续聊天改动无须再次修改数据库；重新编译启动并刷新页面即可。

## 页面入口

| 入口 | 行为 |
| --- | --- |
| 右下角「问问拾光」 | 默认「和拾光聊聊」，支持连续追问；也可选择日记或测量任务 |
| 新增/编辑成长记录正文后的「帮我写一写」 | 在原表单内展开助手，保留正在填写的文字和已选择的照片/视频 |
| 成长数据页「整理测量变化」 | 默认当前孩子和最近90天，可调整日期范围 |
| 空间设置「设置与使用」 | 管理家庭开关并进入助手 |

日记草稿生成标题、正文和标签，提供温柔自然、简洁记录、轻松童趣三种风格。草稿只有完整解析并通过长度校验后才展示，生成期间显示状态，不展示原始 JSON。用户可修改草稿后填入原表单；原表单有文字时须确认替换，仅替换标题、正文和标签，照片视频及其他字段保持原样。独立面板里的草稿会打开新的成长记录表单。两条路径都不会自动保存记录。

测量整理显示服务端计算的统计卡片、千问逐步生成的说明和最近12条参考明细，可跳转原成长数据页。统计覆盖所选范围内全部有效测量，单项缺失值不参与该项统计；只存在一条数据时变化量为未提供，而不是0。千问只负责整理说明，医学判断不属于本功能；生成文本仍需用户核对，不能把提示约束当成医学准确性保证。

## 连续聊天

选择「和拾光聊聊」，输入内容并发送，回答显示为聊天气泡并逐步输出。可以继续输入「再简短一点」「换一种说法」等追问；Ctrl / ⌘ + Enter 可发送，Enter 保留换行。只有服务器完成的问答会加入下一轮上下文；失败时保留输入并标记本轮未完成。

「新对话」清空当前上下文。切换孩子、任务、关闭面板或刷新后不继续原会话；主动关闭/新对话会请求服务端清除对应内存。页面直接关闭、掉网或退出导致清除请求失败时，旧会话按有效期失效。服务端最多暂存256个会话，每个保留最近12轮完整问答且总文字不超过24000字符，超过限制从最早的整轮问答开始移除。闲置30分钟失效，并每分钟清理过期项。

会话按用户、家庭、孩子及会话编号隔离。浏览器只提交 conversationId 和已完成轮次 turn，历史问答由服务端读取，不接收客户端伪造的 system/assistant 历史。模型完成而浏览器未收到 done（例如停止与完成交错）时，下一次会提示状态未同步，需要点击「新对话」。服务端重启后也需要新对话。当前为单应用实例的临时上下文，多实例部署需改为共享会话存储。

普通聊天仅使用孩子基本档案及主动输入的文字，不自动读取记录、测量、照片或视频，也不会自动保存记录。测量整理和结构化日记草稿仍是独立任务，不与聊天相互带入回答。

## 数据与状态

- 服务端每次校验登录身份、当前家庭成员关系和孩子归属，不使用前端传入的 familyId、角色或聊天历史。
- 日记只发送主动填写的笔记、孩子昵称、当前月龄与记录日期；测量任务发送问题、孩子昵称和当前月龄、所选日期范围的统计及最近12条明细。源生日只在后端用于计算月龄，不发送给模型。
- 不读取或发送照片、视频、手机号、分享令牌或 MinIO 凭证。用户自己在输入中写入的个人信息仍会随输入发送，不保证输入匿名化。
- 问答正文不写入数据库；聊天携带本会话近期完整问答，日记和测量仍按单次任务处理。关闭、刷新、重新载入家庭快照或切换孩子会清除面板结果，没有长期聊天历史或跨孩子对话。
- 生成完成前重新校验登录、家庭开关、请求状态及资料指纹；资料已变更则丢弃本次结果并提示重新整理。已完成的显示是当次取数结果，其他设备之后修改数据不会实时推送到当前面板，需刷新/重新整理。
- 点击停止/关闭时取消前端读取并通知后端。后端还每3秒检查会话和请求状态，模型流在取消或总超时后取消订阅；已发送给上游的数据无法撤回，也不能保证上游立即停止计费。
- 用户退出或被移出家庭后不能再次获取上下文。关闭家庭开关将正在运行的请求标记为取消，并拒绝新请求。

## 配置与限额

基础配置位于 `application.yml` 的 `growth.ai`：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` / `GROWTH_AI_ENABLED` | true | 服务端功能开关；各家庭仍需独立开启 |
| `timeout-seconds` / `GROWTH_AI_TIMEOUT_SECONDS` | 90 | 本次订阅的总生成时限，可设10–180秒 |
| `max-output-tokens` / `GROWTH_AI_MAX_OUTPUT_TOKENS` | 1600 | 输出 token 上限，可设100–4000，是否返回完整草稿仍取决于模型 |
| `daily-request-limit` / `GROWTH_AI_DAILY_REQUEST_LIMIT` | 40 | 每用户每天提交次数，失败、停止和无测量数据的请求也计入 |

单次输入最多4000字符，测量范围最多366天；记录数超过5000时要求缩小范围，不静默截断统计。单用户同时只允许一个未过期请求，通过数据库短事务串行登记，不依赖单机内存计数。

`ai_assistant_request` 仅保存请求编号、家庭/用户/孩子编号、任务类型、状态及时间。请求租约为5分钟，应用异常退出后旧 RUNNING 行超过租约不再阻止新请求；它不是聊天历史。目前没有自动清理这张请求表的任务。

外部模型生成期间不持有家庭行锁或事务连接。控制流程日志包含 requestId、任务、状态、总耗时和异常类型，不记录问答正文、资料或密钥。错误文案与 HTTP/SSE 分阶段处理，不向页面透传上游原始响应。

实现中沿用具体模型 options 的 `mutate()` 再设置模型和输出上限，接口依据：[Spring AI 2.0 ChatOptions](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/chat/prompt/ChatOptions.java)。

## 代码与接口

- `GrowthAssistantController`：鉴权入口、输入验证及会话复核。
- `GrowthAssistantService`：千问专用提示、流式输出、总超时、结果校验、异常处理。
- `GrowthAssistantContext`：范围查询、后端统计与资料指纹。
- `GrowthAssistantStore`：家庭开关、并发/次数限制、请求状态。
- `GrowthAssistantConversations`：服务端临时多轮上下文、按用户/家庭/孩子隔离、轮次校验及过期清理。
- `static/growth/assistant.js`、`assistant.css`：独立面板、表单内助手、停止生成及草稿回填。

接口统一前缀 `/api/growth/assistant`，使用同源会话 Cookie 和 `X-Growth-Request: 1`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/settings` | 查询本家庭开关、模型可用配置状态和使用说明 |
| PUT | `/settings` | 管理员提交 `{enabled:true/false}` |
| POST | `/stream` | 提交 requestId、childId、task、question、from、to、style、consent；聊天另需 conversationId、turn（第一轮为0） |
| POST | `/requests/{requestId}/cancel` | 取消本人本家庭的请求 |
| DELETE | `/conversations/{conversationId}` | 清除本人本家庭对应的临时聊天上下文 |

task 仅允许 chat / diary / measurements，style 仅允许 gentle / simple / playful。SSE 事件为 meta、stage、delta、draft、done、error，结构为 `{type,data}`。未收到 done 的回答不能视为完整结果；失败时前端清除不完整草稿或将聊天气泡标记为未完成。空测量范围使用后端固定提示，不调用千问。

## 手动验收

### HTTP 部署下的会话编号兼容

公网 HTTP 页面可能报 `crypto.randomUUID is not a function`。该错误发生在前端生成请求/会话编号时，请求尚未发送到千问；`localhost` 被浏览器视为可信上下文，因此本地可能正常。

前端现已优先使用原生 `randomUUID`，不可用时通过 `getRandomValues` 生成符合 UUID v4 格式的编号；不会退回普通伪随机数。两个编号均在进入发送状态前生成，避免生成失败后卡在忙碌状态。首页脚本地址增加了版本参数以更新缓存。

该修复需要将修改后的源码重新打包部署才会进入服务器上的 JAR。部署后刷新页面，在公网 HTTP 地址验证首次发送、连续追问和新对话；没有调用模型或执行自动化测试。

### 业务验收

以下项目均待用户执行，不是已通过的测试：

1. 执行升级 SQL 并启动，管理员可开启/关闭；普通成员只有使用入口，无开关权限，分享访客无访问权限。
2. 输入两句真实笔记生成草稿，编辑后填入；不点击保存时数据库无新增记录。原表单有文字需确认替换，取消替换后原文仍在，已选媒体不丢失。
3. 测量任务覆盖无记录、一条记录、缺失头围、同日多次、负变化及跨月情况；核对卡片中的首末值、日期与变化量，再核对千问文字是否忠于数据。
4. 切换孩子、关闭弹窗、退出登录、停止生成、网络提前断开时没有串用上下文或可误保存的半截草稿。
5. 生成期间修改或删除测量，完成时提示资料变化；成员被移出、开关关闭时正在生成的请求停止，重新提交被拒绝。
6. 更换其他家庭 childId、伪造角色、向问题里写入越权/任意 SQL 指令，均不能读到额外数据或触发写操作；修改为任意 provider / model 字段不影响固定千问调用。
7. 同用户多标签页并发请求、重复 requestId、超每日次数、模型未配置、模型超时、草稿格式不完整等情况都有错误提示，成长网站其他功能仍可用。
8. 调试台原有 `/api/ai/**` 仍按原用途工作；它与家庭助手接口独立，既有对外部署限制仍适用。
9. 在「和拾光聊聊」输入一件真实小事，再追问「把刚才的回答缩成一句话」，确认结合上一轮；新对话、切换孩子/任务之后不继续旧上下文。
10. 停止或掉网后重试，过期/服务重启后追问、篡改 turn、换用户访问相同 conversationId 时，没有串用别人的对话；必要时提示新对话。超过12轮或24000字符后按整轮截断，页面提示较早内容已省略。
