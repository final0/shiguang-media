# QQ 邮箱验证码与待办提醒

本次为源码实现及阅读审查；未编译、未运行测试、未执行数据库脚本、未修改线上配置，也未使用提供的授权码发送真实邮件。

## 页面与规则

- 注册保留手机号／密码登录，新增必填 QQ 邮箱与六位数字验证码。验证码由统一发件邮箱发送，用户不需要 QQ 密码或 SMTP 授权码。
- 只接受 `@qq.com`，邮箱统一去除首尾空格并转小写；一个邮箱只能绑定一个账号。已有用户邮箱为空，原登录不受影响，可在「我的个人资料 → QQ 邮箱与提醒」补充验证。
- 更换邮箱须验证新邮箱验证码与本人当前登录密码。个人资料中可以关闭／开启邮件提醒。
- 「待办提醒」支持新增、编辑、暂停、标记完成、删除及最近30次投递记录。每人最多保留100条，只管理自己的提醒，只发给自己的已验证邮箱；管理员也不能管理其他成员的个人提醒。
- 可选关联当前家庭的活动孩子。时间全部使用北京时间，支持仅一次、每天、每周。编辑／重新安排需要选择未来时间，保存后取消旧版本未发送的任务。
- 发送记录中的「已提交邮箱服务器」不代表送达或已阅读。QQ 邮箱可能限流或将邮件放入垃圾箱，不能保证精确到秒送达。

## 邮件外观

提醒和验证码统一使用拾光的奶油白 `#f8f7f2`、纸白 `#fffefa`、鼠尾草绿 `#71866d` 配色。页头为「拾光 / LITTLE MOMENTS」，正文使用卡片，页尾保留品牌寄语。提醒邮件突出北京时间、事项和多行备注；无备注时隐藏备注区，延迟补发时增加暖色提示。验证码邮件用大号等宽数字展示完整6位验证码，保留前导零及5分钟有效期说明。

共享外框为 `src/main/resources/growth/mail/layout.html`，具体内容由 `GrowthMailTemplate` 生成；所有用户标题、备注先做 HTML 转义。占位符仅在原模板替换一次，用户输入不会作为模板或 HTML 执行。邮件使用表格布局、内联样式、系统字体，不加载外部图片／脚本／CSS，也不增加图片追踪请求。

`GrowthMail` 使用 UTF-8 MIME 邮件，同时提供 HTML 和纯文本正文，发件人显示名为「拾光 · 成长记录」。[Spring MimeMessageHelper 文档](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/mail/javamail/MimeMessageHelper.html#setText(java.lang.String,java.lang.String))说明了两种正文的选择机制。实际字体、圆角和深色模式由邮箱客户端决定，需在 QQ 邮箱客户端手动查看；尚未执行真实邮件发送或客户端视觉验证。

此项只需手动编译并重启应用，HTML 资源随 JAR 打包；SMTP 授权码、数据库和 Nacos 配置无需增加字段。手动验收时可安排一条含中文、换行、`< > &`、较长备注的提醒，并查看手机及桌面收件效果；也可用正常注册／绑定流程查看验证码邮件。

## 验证码

使用 `SecureRandom` 生成000000—999999的六位数字，Redis保存随机盐、验证码摘要、尝试次数与状态，不保存明文验证码。前端、日志和接口响应不包含验证码；邮件正文才包含验证码。

有效期5分钟；同邮箱发送间隔60秒、每小时最多10次；单来源地址每小时100次、系统每小时200次。服务端取实际连接地址，不信任任意客户端 `X-Forwarded-For`；当前代理部署可能使多个用户共用来源限额。这是应用限制，并非 QQ 官方配额。

验证码绑定用途、邮箱和当前浏览器会话；注册还绑定手机号，更换邮箱绑定登录用户。不得跨用途、跨用户或跨会话复用；同一流程重发会替换旧码。比较、计错和消费通过Redis Lua原子完成，连续错误5次失效，成功后一次性消费。Redis故障拒绝校验，不绕过邮箱验证。

先校验手机号、邮箱、邀请码等条件，再消费验证码并写入用户。Redis和MySQL不构成分布式事务；验证码消费后如果数据库失败，需重新获取验证码，不能无限复用旧验证码重试。发送失败也可能占用本次发送限额，至少60秒后重试。应用或浏览器会话重启后应重新获取验证码。

## 调度、并发与重试

`growth_reminder` 保存业务计划，`reminder_delivery` 保存每次投递。独立扫描线程每30秒扫描到期计划，在家庭行锁事务内创建唯一 `(reminder_id, revision, scheduled_ms)` 记录并推进下一次时间。数据持久化到 MySQL，Redis不是提醒任务存储。

提醒的到期判断、重试和租约统一通过 `GrowthStore.currentEpochMillis()` 读取数据库 epoch 毫秒，不将 `CURRENT_TIMESTAMP` 映射为 Java `Timestamp` 后再换算。仅设置 JDBC `connectionTimeZone=Asia/Shanghai` 不会修改 MySQL 会话时区；数据库为 UTC 时，旧换算会把扫描时间推迟8小时。本次修复只切换提醒的时钟，不修改已有计划时间或其他业务的注销期限，不需要执行 SQL 迁移。

启动日志 `Reminder scheduler started` 表示扫描线程已注册；首次扫描及之后每5分钟输出 `Reminder scan` 心跳，发现到期计划或待投递邮件时也输出，含数据库／应用北京时间和任务数量。未配置邮件时输出 `Reminder scan skipped`；SMTP成功接收输出 `Reminder SMTP accepted`，失败输出固定结果码。日志不包含邮箱地址、邮件内容或授权码。

提醒页可见时每10秒刷新列表，切走页面后停止，打开弹窗或焦点位于列表中时暂停替换。自动刷新失败保留原列表，仍可手动刷新。重启新代码后，已到期且仍符合发送条件的一次性任务会自动补发；先前已暂停／取消的任务需自行重新安排。

发送使用2个线程、8个排队槽位的独立有界线程池。每次发送前在事务中取得任务、核对所属关系／邮箱版本／账号注销／孩子状态，使用2分钟租约和随机认领令牌；网络发送在事务外进行，避免长期占用数据库锁。其他Pod不能同时认领有效租约内的同一任务；进程退出后，租约过期可再次领取。

每次投递最多尝试3次，一般故障在1分钟、5分钟后重试；认证失败直接标记失败。只保存固定结果码，不记录邮件正文、邮箱授权码或带敏感内容的异常消息。

一次性任务在服务恢复后补发；周期任务只补最近一次，按最初时间计算之后的周期，不随扫描延迟漂移。系统停用产生的自动暂停与单纯服务器停机不同：恢复可用后周期任务跳过停用期间的提醒，只安排未来；已过期的一次性任务转为手动暂停，需本人重新安排。

SMTP外部发送不能与数据库提交成为一个原子事务。若邮件已发出但进程在写回状态前退出，重试可能重复投递；暂停／注销／邮箱更换无法撤回已经开始发送的邮件。队列会拒绝后续新发送，不承诺绝对零重复或撤回在途邮件。

## 和原功能的衔接

| 操作 | 提醒处理 |
| --- | --- |
| 申请个人／家庭注销 | 对应提醒自动暂停、排队投递取消；取消注销后按未来计划恢复 |
| 正式注销个人 | 清除邮箱、邮箱验证状态、个人提醒及发送记录，邮箱允许重新注册 |
| 正式注销家庭 | 清理家庭内全部提醒与投递；其他成员个人邮箱保留 |
| 孩子档案移入回收站 | 关联提醒自动暂停，恢复档案后按未来计划恢复 |
| 彻底删除孩子档案 | 清理关联提醒及投递记录，防止外键残留 |
| 移出成员 | 清理该成员在原家庭中的提醒及投递 |
| 更换邮箱／修改接收设置 | 邮箱版本递增，取消旧版本排队投递；已排队的一次性提醒需重新安排 |

1. 确保前面的 `upgrade-ai-assistant.sql`、`upgrade-account-deletion.sql` 已执行；然后在当前业务数据库执行 `src/main/resources/growth/upgrade-email-reminders.sql`。新增用户邮箱字段、唯一索引和两张表，可重复执行。全新数据库直接执行新版 `schema-mysql.sql`。
2. 刷新 Maven，新增 `spring-boot-starter-mail` 已写入 POM，编译及打包由你手动执行。
3. 本地默认发件人为 `2976737985@qq.com`，地址 `smtp.qq.com:465`，使用SSL和服务端证书校验。提供的授权码位于工作目录下 `config/mail-secrets.properties`，已加入 `.gitignore`，不在 `src/main/resources`，不会打入JAR。启动工作目录需为项目根目录，或通过环境变量 `QQ_SMTP_AUTH_CODE` 注入。环境变量可覆盖本地默认授权码。不要将该文件提交或放入公开资料。
4. 服务器通过 `SPRING_CONFIG_LOCATION=file:/runtime/application.yaml` 只加载Nacos导出的配置，**不能只修改JAR内的application.yml**。将 `deploy/k8s/mail-nacos-snippet.yaml` 中的 `spring.mail` 合并进Nacos现有 `spring` 节点，不覆盖数据库／Redis配置。
5. 在已有 `shiguang-runtime` Secret 中增加键 `QQ_SMTP_AUTH_CODE`，值为已提供的授权码。保留现有其他键；Deployment 已经通过 `envFrom` 引用该 Secret，无需在 manifest 中写明文凭证。Nacos只保存 `${QQ_SMTP_AUTH_CODE:}` 引用。不要重新运行初始化脚本覆盖整份Secret。
6. 按现有部署流程更新镜像并重建Pod，使Nacos和Secret生效；确保服务器可以连接QQ SMTP的465端口。只填写发件邮箱账号和SMTP授权码，不使用QQ登录密码。

未配置SMTP时原账号登录仍可用，提醒页面显示邮件未配置，新注册因无法发验证码而不能完成。Redis不可用时同样不能跳过新注册验证。

## 接口

统一前缀 `/api/growth`，沿用自定义防跨站请求头。注册发码为匿名接口，其余均校验当前登录者。

| 方法与路径 | 请求／行为 |
| --- | --- |
| POST `/auth/email-code` | `{phone,email}`，发送注册验证码 |
| POST `/auth/register` | 原字段加 `email,emailCode`；提交成功后仍走可选头像上传 |
| GET `/account/email` | 本人邮箱、验证状态及接收设置 |
| POST `/account/email-code` | `{email}`，发送本人新邮箱验证码 |
| PUT `/account/email` | `{email,code,currentPassword}`，绑定／更换邮箱 |
| PUT `/account/email-preference` | `{enabled:true/false}` |
| GET／POST `/reminders` | 本人列表／新增 |
| PUT／DELETE `/reminders/{id}` | 本人修改／删除 |
| PUT `/reminders/{id}/state` | `{state:"PAUSED"}` 或 `{state:"COMPLETE"}` |
| GET `/reminders/{id}/history` | 本人最近30条投递记录 |

新增／编辑正文：`{title,content,childId,time,cadence}`。`childId` 可空；`time` 使用北京时间本地时间字符串，例如 `2026-10-01T09:00`；`cadence` 为 `ONCE`、`DAILY`、`WEEKLY`。
