# 账户注销与 12 小时恢复期

入口：登录后打开「我的个人资料 → 申请注销账户」。输入当前密码并确认后立即停用；恢复期限固定为申请提交时数据库时间加 12 小时，刷新页面、重新登录或注册不会延长。

## 业务规则

| 情况 | 恢复期内 | 到期后 |
| --- | --- | --- |
| 普通成员注销 | 本人停止访问；同手机号登录或注册提示倒计时，可用原密码取消 | 清除手机号、昵称、密码和头像，解除家庭关系；共享记录与评论保留，作者变成「已注销用户」 |
| 任一管理员注销（包含被授权的管理员） | 整个家庭停用，访客分享也不可访问；只有发起账号能取消 | 删除家庭、孩子档案（含档案回收站）、成长记录（含回收站）、照片视频、测量、接种、标签、评论、分享、通知、操作日志和 AI 使用状态 |
| 其他家庭成员 | 可看到家庭停用提示与截止时间，不能代替发起者取消 | 保留个人账号和头像，使用原手机号与密码登录后，可新建家庭或填写邀请码加入家庭 |

恢复只取消本人发起的注销申请，不新建账号或家庭、不改变原有角色和记录的归档/回收站状态。家庭内存在另一份未取消的注销申请时，该申请仍然有效。停用期间被取消的 AI 请求不会重新生成。

无论是否关闭页面、是否在线，12 小时截止后都不能恢复。页面每半秒更新显示；后端独立检查期限，修改浏览器时间不能绕过。注销后手机号只有在后台账户清理事务完成后才可重新注册，重新注册不会恢复旧数据。

## 数据与可靠性

- `account_deletion` 存储申请人、家庭、范围和数据库时钟对应的毫秒截止时间，不存储手机号或密码。它是判断注销状态的依据。
- Redis 使用 `shiguang:account-deletion:sweep` 的 30 秒租约减少多个 Pod 重复扫描；不依赖 Redis 过期事件。Redis 失败时退回 MySQL 行锁，60 秒后再次尝试 Redis。
- 清理器每 15 秒运行一次，结合 Redis 租约，正常情况下约 30 秒扫描一次。截止时立即不可恢复；数据库实际删除在后续扫描事务完成，故障时可能延迟，重启后补偿执行。单次最多处理 50 份申请，积压会继续扫描。
- 取消、注销提交、家庭写操作和到期清理使用家庭行锁；清理任务再次校验数据库期限，可在多实例下重复调用。资料删除及 MinIO 待清理对象入队处于同一数据库事务中，失败回滚并重试。
- MinIO 文件交给现有 `media_cleanup` 队列异步删除。服务正常时每分钟处理一批；MinIO 不可用时保留任务，恢复后继续。保留的其他成员个人头像不删除；未完成上传也沿用原有上传意图清理机制。
- 为维持共享内容的作者外键，注销账户保留匿名占位行（随机不可登录手机号、随机密码哈希、空头像和固定昵称），原手机号释放。此次清理不处理应用之外的人工备份。

## 升级步骤（手动）

1. 在项目实际使用的 MySQL 数据库中执行 `src/main/resources/growth/upgrade-account-deletion.sql`。此脚本只新增表和索引，可重复执行；必须先执行再部署新代码。新数据库的 `schema-mysql.sql` 已包含此表。
2. Maven 已新增 `spring-boot-starter-data-redis`，重新加载依赖并由你编译、打包。
3. 核对 Nacos 当前配置中的 Redis 地址是 **Pod 可以访问的 Docker 宿主机地址**。在既有 `spring.data.redis` 节点中合并如下超时配置，保留当前可用地址、端口、密码；不要新增第二个 `spring` 根节点，也不要把密码填入前端配置。

   ```yaml
   spring:
     data:
       redis:
         connect-timeout: 1s
         timeout: 1s
   ```

   项目的 `application-mysql.yml` 已同步这两项。Nacos 外部配置可能覆盖 JAR 内配置；现有部署通过 initContainer 拉取配置，更新配置后需重建 Pod。

4. 按 `deploy/k8s/README.md` 中的现有流程替换 JAR、制作新标签镜像并更新 Deployment。此次源码修改没有替你编译、执行 SQL、修改 Nacos 或发布服务器。

## 手动验收建议

使用独立测试家庭和测试照片，不要缩短正式家庭的恢复期限。

1. 普通成员申请，确认所有旧会话停止访问，其他家人正常使用；重复登录、注册都出现相同截止时间。错误原密码不能取消，正确密码可恢复，期限不会被刷新延长。
2. 被授权的管理员申请，检查全家登录、邀请新成员、旧会话写入、照片视频访问、访客分享都受限制；其他管理员不能代为取消。申请人取消后检查孩子、记录、测量和角色保留。
3. 测试家庭包含正常记录、回收站记录、归档孩子、评论、标签、照片视频和 AI 使用状态。到期后检查数据库完整清理、`media_cleanup` 对象最终删除；其他成员原密码可登录并重新加入/创建家庭。
4. 在测试环境让申请到期，尝试同时取消及多实例扫描，确认不能在期限后恢复，且清理失败能重试。确认原手机号可以在清理完成后注册全新账号。
5. 恢复期内重启应用或 Redis，确认截止时间保持不变。临时断开 Redis / MinIO，分别检查数据库清理继续执行 / 文件任务保留重试。
6. 管理员调整其他成员权限与提交注销并发时，注销范围应以最终锁定的角色为准；未勾选家庭删除确认的请求不能因角色刚升为管理员而删除家庭。

以上为验收清单，尚未执行编译、自动化测试或部署联调。
