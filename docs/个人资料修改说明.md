# 个人资料修改

本次完成源码修改及阅读审查，未编译、启动、执行 SQL、调用接口或进行浏览器与 MinIO 联调。下述流程待手动验证。

## 使用

重新编译启动并刷新网站，点击右上角头像/昵称进入「我的个人资料」。管理员与普通成员都能使用，只能修改自己的账号。

- 昵称：最多40个字符，不能为空；保存后刷新顶部名称、家庭成员和记录/评论署名。
- 头像：选择 JPG / PNG，最多2 MB、800万像素，可预览后单独保存，也可恢复默认头像。服务端按实际格式解码，居中裁切成512×512的 JPEG，重编码去除原图元数据后存入现有私有 MinIO 桶。不接收头像外链、客户端对象路径或目标用户ID。
- 手机号：11位，以1开头，不能与当前相同或已被其他账号使用；校验当前登录密码。尚未接入短信验证，手机号所有权未通过短信核验。
- 密码：校验当前密码，新密码输入两次且一致，8–60字符、最多72个UTF-8字节，不能与当前密码相同；使用已有 BCrypt 存储。

手机号或密码修改成功后返回登录页。手机号修改后密码保持不变，使用新手机号登录；密码修改后使用新密码登录。其他旧会话在下次接口鉴权时失效，已在处理的普通请求可能继续完成；AI流也按已有周期鉴权终止。

这次为登录会话加入凭证摘要校验，升级前的旧会话需要重新登录一次。没有修改或暴露用户原密码；凭证摘要只存在服务端会话中，不返回浏览器。修改手机号时同时重新加盐生成同一密码的 BCrypt 哈希，避免改回旧手机号使旧会话重新生效。

示例账号可以体验昵称和头像修改，不允许修改手机号或密码；正式登录信息需要注册正式账号。

## 注册时选择头像

「创建 / 加入家庭」页面新增选填头像，支持预览、更换和「使用默认头像」。不选择文件时沿用昵称首字默认头像，昵称修改后预览同步变化。选择 JPG / PNG，最多 2 MB、800 万像素；浏览器在注册前检查文件大小、文件头、能否解码及尺寸，服务端继续独立校验并居中裁剪。

流程复用现有两个接口：先 `/auth/register` 创建账号并建立登录会话，再以该会话调用 `/account/avatar` 上传至 MinIO。不开放匿名上传，不接收目标用户 ID，创建家庭和通过邀请码加入家庭均支持。

头像上传失败不会撤销已创建的账号。页面加载账号后检查头像状态；仍无头像时显示默认头像，并明确提示注册成功、可在「我的个人资料」重试。注册成功但家庭数据加载失败时改为登录入口并保留手机号，避免重复注册。提交期间锁定表单与登录切换按钮，预览 URL 在切换页面、更换图片及完成注册时释放。

手动验证项：不选头像注册、选择 JPG/PNG 注册、使用邀请码加入并上传、取消已选头像、超限/损坏文件、MinIO 上传失败后直接登录及修改头像。上述功能仅完成源码修改和阅读审查，未编译、未进行注册或上传联调。需要重新打包部署并刷新页面后上线。

## 数据与接口说明

复用现有 `app_user.phone / nickname / password_hash / avatar` 及 `media_cleanup`，不增加表或字段，不需要新的升级 SQL。此前项目的 MySQL 完整结构和 MinIO 配置应已就绪。

头像仅通过登录后的家庭接口读取；不同家庭不能读取该头像，访客分享不包含头像。快照只增加头像存在标志，完整手机号只在本人的 `/account` 响应中提供。其他家庭成员不会通过快照看到手机号、密码哈希或存储对象路径。

头像属于账号资料，不计入家庭成长记录的照片/视频配额。旧头像替换、恢复默认或上传失败后进入已有清理队列；队列会同时检查成长媒体和用户头像引用，避免删除仍在使用的文件。网络上传在头像更新事务外进行，失败时保留原头像。临时处理文件在请求结束后删除。

| 方法 | 路径（前缀 `/api/growth`） | 行为 |
| --- | --- | --- |
| GET | `/account` | 查询本人昵称、手机号、头像标志、创建时间和示例标志 |
| PUT | `/account` | `{nickname}` 修改本人昵称 |
| PUT | `/account/phone` | `{phone,currentPassword}` 修改本人手机号并退出旧会话 |
| PUT | `/account/password` | `{currentPassword,newPassword,confirmPassword}` 修改密码 |
| POST | `/account/avatar` | multipart 字段 `file` 上传本人头像 |
| DELETE | `/account/avatar` | 恢复本人默认头像 |
| GET | `/users/{id}/avatar` | 读取同家庭用户头像，需要登录 |

操作沿用会话鉴权和 `X-Growth-Request: 1`，没有“管理员代改他人账号”接口。操作日志仅记录修改类型，不记录密码或新旧手机号。

## 手动验收

1. 管理员和普通成员分别改昵称、上传头像、恢复默认，核对顶部、成员列表、记录作者和评论；无头像/读取失败时显示文字头像。
2. 上传超限、非图片、伪装成JPG的文件，验证拒绝且保留旧头像；MinIO暂不可用时可重新选择文件重试。
3. 改手机号时分别输入错误密码、已占用手机号和未占用手机号；成功后旧手机号不可登录，新手机号配原密码可登录。
4. 改密码时分别检查原密码错误、两次不一致、长度超限和正常修改；正常修改后旧密码无效。
5. 两个浏览器登录同一账号，修改手机号或密码后另一个浏览器再访问接口应要求重新登录；修改回旧手机号不能恢复旧会话。
6. 其他家庭访问头像、伪造账号ID提交资料修改，不能读取或修改越权账号。
7. 头像替换后的清理任务正常删除旧对象，仍被 `app_user.avatar` 引用的新头像持续可读。
